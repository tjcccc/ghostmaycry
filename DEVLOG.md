## 2026-10-26 — v0.2.1 — Agent session env no longer leaks into launched agents

- **Bug.** A Claude Code started from the panel in Ghostty warned "Transcript saving is off — inherited CLAUDE_CODE_CHILD_SESSION marker" and its session never appeared in history. Cause: the v0.2 visual check started Ghostty with `nohup` from an agent shell, so Ghostty, and every shell it opened, carried that session's `CLAUDE_CODE_*` (and the scratch `GHOSTMC_HOME=home`). Fixed for the user by restarting Ghostty; `CLAUDE.md` now says to use `open -a Ghostty`.
- **Hardening.** `ghostmc_core::agent::clear_session_env` removes `SESSION_ENV_VARS` (Claude Code's session markers, plus Codex's `CODEX_THREAD_ID`, `CODEX_TOOL_CALL_ID`, `CODEX_SANDBOX*` and `CODEX_CI`, read from the installed Codex binary) at the start of the CLI (after the `hook ingest` early return) and the desktop app. User configuration such as `CODEX_HOME` and `CLAUDE_CODE_PLUGIN_DIRS` stays. tmux servers, Linux and custom terminals started by ghostmc now begin clean.
- Validation: new `ghostmc-cli/tests/session_env.rs` runs `ghostmc project add` and `ghostmc new` with the markers set, on a private `TMUX_TMPDIR`, and checks the new server's global env: markers gone, `CODEX_HOME` kept. It fails with the scrub disabled. fmt, workspace clippy and `cargo test --workspace --locked` (92) pass; `libc` still 0.2.186.
- Open: on macOS, Ghostty windows opened over AppleScript take Ghostty's own env, so a Ghostty started from an agent shell still leaks; only the `CLAUDE.md` rule guards that. A tmux server already started from an agent shell keeps its global env until it restarts (`new-session -e` can't unset). The marker list follows today's Claude Code and Codex; new markers need adding.

## 2026-10-25 — v0.2.0 — Menu-bar panel, workspaces, agent briefs

- **Desktop redesign.** The four-tab window is gone, replaced by a menu-bar panel on macOS (a normal window on Linux) with a workspace list on the left and the selected workspace's agents on the right. Right-click a workspace to Pin, Rename (new IME-capable text input) or Remove it; `+` opens Ghostty in `[desktop] new_terminal_dir`; Settings sets that folder and offers Quit. The panel follows the light/dark appearance. The status item is `objc2` (already in GPUI's tree, only features added); the icon is Font Awesome Free's ghost (CC BY 4.0), rendered with `resvg` as a template image, with a dot for news.
- **Workspaces** (`ghostmc-host::workspace`, pure, 6 tests): saved projects claim the Ghostty tabs in their folders; other windows become live workspaces named after the first tab, saved on Pin/Rename. Agents are tied to tabs by tty or tmux pane, and by folder only when exactly one tab matches.
- **Agents.** `hook ingest` records the agent's terminal and the pid that owns it (schema v2: `tty`, `tty_pid` on events and runs). A run whose tty owner exited is Disconnected, so a reused tty number can't attach an old agent to a new tab. The end-of-turn brief (`Stop.last_assistant_message`, 600 chars) travels in `IngestEvent.brief` and is held only in host memory (protocol 1.1, `AgentRuns { briefs }`, cleared by `ghostmc api`). ADR §8 updated.
- Also: `ghostty::launch` with empty argv opens a plain shell; `config::set_new_terminal_dir` edits `config.toml` in place with `toml_edit`; `Request::IngestEvent.event` is boxed (same wire format).
- Validation: fmt and clippy (`--workspace --all-targets -D warnings`) clean, `cargo test --workspace --locked` 91 passed, `libc` still 0.2.186. A real `hook ingest` captured `/dev/ttys004` and left no brief on disk in direct mode. The panel ran on macOS against a scratch `GHOSTMC_HOME`: status item present, no Dock icon, a click opens the panel under the menu bar.
- Visual check on macOS 27 with Ghostty 1.3.1, after the user granted Screen Recording. It found three bugs, all fixed:
  - The Ghostty list script failed outright because 1.3.1 has no `tty`/`pid` terminal properties. They are now read optionally. Since v0.1 the listing had never worked on a real Ghostty.
  - Clicks on the right-click menu also reached the tab row beneath it, which focused Ghostty and closed the panel. Fixed with `.occlude()`.
  - The folder fallback skipped every agent that had a tty, so with no tab ttys an agent in Ghostty was never shown. It now trusts a tty mismatch only when the tabs report ttys (new test).
  - Also, a Ghostty error now shows in the empty list.
- Verified by real clicks:
  - icon toggle and close on an outside click;
  - live workspace with tabs and branch;
  - Pin, Rename (including Chinese text) and Remove confirm;
  - Settings;
  - an agent row with its brief, with the brief absent from the DB and WAL;
  - `ghostmc focus <id>`.
- **Collapsible right pane** (user feedback): the panel opens with only the list (330 pt). Clicking a workspace or Settings opens the pane (760 pt). Clicking it again, or Escape, closes it. The status line moves under the list while the pane is closed. The panel keeps its top edge and stays under the icon: `statusbar::set_frame` sets the NSWindow frame through `raw-window-handle`, deferred to a foreground task because it re-enters GPUI's resize callback. The 🔔 clears only when the pane is actually opened. Saved-folder rows with no open tab now get their git branch from the same lookup as tabs; `ListProjects` returns none.
- **Cards** (user feedback): the list and the right pane are separate rounded cards with a gap. Each is as tall as its content, up to 520 pt, and scrolls beyond that. The menu-bar window is transparent with a fixed height, and the cards draw their own shadows; the NSWindow shadow is off. A click on the empty area closes the panel; the cards and the context menu stop that mouse-down. On Linux the same cards sit on an opaque window.
- **Liquid Glass** (user request): on macOS 26+ each card sits on an `NSGlassEffectView` inserted below GPUI's view in the panel's content view, the same way GPUI adds its own blur view (`glass.rs`, guarded by a runtime class check). Each card has an invisible `canvas` that records its bounds during prepaint; a final paint step hands them to the backdrop, which moves the glass views and hides the pane's glass while the pane is closed. On glass the cards paint no fill, border or shadow, and `theme::on_glass` swaps in translucent hover, selection, button and border tints. The right-click menu became a native `NSMenu` (`context_menu.rs`), which macOS draws with its own glass. A drawn menu can't use glass: it overlaps the list card, whose text would show through. The menu pops up from a spawned task, so its tracking loop doesn't run inside a GPUI event. Remove now asks inline in the workspace, with Remove and Cancel. Linux keeps the drawn menu. The glass is dropped when the panel closes. Style changes for a macOS look: 16 pt card radius, inset rounded selection with no separators between workspaces, capsule buttons, and a rounder menu. Older macOS and Linux keep solid cards.
- **App bundle** (`scripts/build_macos_app.sh`): builds `Ghost May Cry.app` into `target/macos`, with `LSUIElement` (no Dock icon), an `NSAppleEventsUsageDescription` (needed to script Ghostty), an `LSEnvironment` PATH that includes Homebrew (Finder launches get only the system PATH, which has no `tmux`) and an ad-hoc signature (`SIGN_IDENTITY` overrides it). Built, `codesign --verify` passed, and it launches as a UIElement. Untested: a launch from Finder, so the `LSEnvironment` PATH is unverified. No app icon yet; the CLI is not bundled.

## 2026-10-23 — v0.1.0 — First vertical slice: registry, tmux, host, CLI, hooks, SSH remote, GPUI desktop

- Rust 2024 workspace with seven crates: `core`, `tmux`, `protocol`, `platform`, `host`, `cli`, and `desktop` (the GPUI app, excluded from the default members). Architecture, identities and the security model are in `docs/adr/0001-architecture.md`.
- **Registry.** SQLite (rusqlite, bundled) holds projects, device-specific locations, remote links and git/worktree detection. Migrations run through `PRAGMA user_version`, and the store refuses a database with a newer schema.
- **tmux.** A session is identified by socket + server pid + start time + `$id`, never by name. On create, the location, project and token tags are set atomically in the same command list as `new-session`. Creation is idempotent under a per-location flock: six concurrent creators produce one session. A cwd match is only a candidate the user must choose; the CLI exits with code 2 when a choice is needed. Observe uses `-f read-only,ignore-size`.
- **Agents.** `hook install` and `hook uninstall` handle Claude Code and Codex hooks without touching other handlers: they back up the config first and refuse invalid JSON. `hook ingest` attributes events by session token, then tmux pane, then cwd; states run from running and needs-approval through ended, disconnected and stale. Prompts and assistant text are never stored.
- **Host.** `ghostmc host run` serves a Unix socket and checks the peer uid. The CLI falls back to direct mode when no host is running. Remote access uses `ssh -T -o BatchMode=yes … ghostmc api`, which is read-only unless `--allow-write`; remote attach goes through `ssh -t`.
- **Ghostty.** On macOS, AppleScript lists, focuses and launches terminals, taking values only through argv. A terminal is linked to a tmux client only by an exact tty match. On Linux, `ghostty +new-window` is used; Linux has no list, focus or new-tab, so those report as unsupported.
- **Desktop.** The GPUI app shows projects, sessions, agents, the git diff and files, and updates live from hook events.
- Validation: `cargo test --workspace` (77 tests) and clippy clean. `scripts/verify_remote_attach.py --device loop` passed 12/12 over loopback SSH. The desktop app ran under Xvfb (screenshots in `docs/images/`). The host idles at about 16 MB RSS and 0 % CPU. All of this ran on an Ubuntu cloud container. Not run yet: macOS Ghostty and AppleScript, GPUI on macOS, Fedora/Wayland, real Claude Code and Codex binaries firing hooks, and a Tailscale run between two real machines. Details are in `docs/MVP.md`.
